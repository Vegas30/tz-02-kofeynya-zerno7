# Разбивка на задачи

Размер: S до часа, M 1–3 часа, L больше. «Готово, когда» всегда проверяемо. Номера G-xx — требования из [spec.md](spec.md).

Порядок для исполнителя: фазы 1 → 2 → 3 → 4 строго по очереди; внутри фазы 2 страницы независимы, кроме P6 → P7.

## Фаза 0. Подготовка (делает человек, один раз для всех)

| ID | Задача | Размер | Готово, когда |
|---|---|---|---|
| T0.1 | Закрыть пробелы данных в `js/data.js` (контакты, соцсети, преподаватели, чай и «без лактозы», сорта зерна) или явно решить «оставить пусто». Если придумываете демо-данные, придумайте один раз, для всех | M | В файле нет `TODO(заказчик)` без решения; решения D1–D13 из [spec.md](spec.md) подтверждены или изменены |
| T0.2 | Положить пакет (`AGENTS.md`, `js/`, `tools/`, `docs/`) в репозиторий и закоммитить в `main` | S | `python tools/check.py` запускается без ошибок самого скрипта (проверки при этом падают, сайта ещё нет) |
| T0.3 | Создать ветки исполнителей от одного коммита и отдельную папку (worktree) на каждую | S | 4 ветки `impl/<модель>`, одинаковый стартовый коммит |
| T0.4 | Подключить репозиторий к Vercel, проверить, что ветки получают свои адреса | S | Тестовый push в ветку даёт адрес предпросмотра, который открывается без входа (или Lighthouse запускаем локально) |
| T0.5 | Начать журнал: записи 001–002 уже в [prompts.md](prompts.md), дополните «что исправлено вручную» | S | Файл на месте, записи заполнены честно |
