# Архитектура сайта «Зерно 7»

Требования — [spec.md](spec.md), данные и события — [data-schema.md](data-schema.md), что даёт полное ТЗ — [scope-site.md](scope-site.md).

## 1. Принципы

1. **Без сборки и фреймворков** (ТЗ 3.1: React, Next.js и подобное не принимаются). Чистые HTML, CSS, JS.
2. **Работает по двойному клику (`file://`) и на Vercel одинаково.** Отсюда запреты: нет `<script type="module">`, нет `fetch()` локальных JSON-файлов. Данные лежат в `js/data.js` как обычный скрипт. (Запрос формы на внешний адрес Apps Script это другое, он разрешён.)
3. **HTML содержит содержание, JS добавляет поведение.** Тексты, цены и заголовки лежат в разметке: это видят поисковики, и Lighthouse SEO проходит.
4. **Код должен быть объясним построчно.** При приёмке заказчик выбирает любой фрагмент из `js/`, и вы объясняете каждую строку. Поэтому: без библиотек, без минификации, без «хитрых» однострочников, у каждой функции комментарий по-русски. Цель — весь JS не больше 600 строк.
5. **Факты только из `js/data.js`.** Чего там нет, на сайте не публикуется.
6. **Относительные пути** (`css/base.css`), чтобы работало и локально, и на Vercel.
7. **Сайт готов к следующим этапам ТЗ:** тег GA4 вставляется в `<head>` готовых страниц, события уже описаны атрибутами, форма уже в формате приёмника.

## 3. Подключение к странице

Скрипты в конце `<body>` с `defer`, в этом порядке:

```html
<script src="js/data.js" defer></script>
<script src="js/analytics.js" defer></script>
<script src="js/common.js" defer></script>
<script src="js/courses.js" defer></script>   <!-- скрипт только этой страницы -->
```

`analytics.js` и `data.js` подключаются на **всех** страницах, включая `404.html`: на каждой странице нужно уметь сохранить UTM-метки и отправить события.

CSS в `<head>`: `tokens.css` → `base.css` → `components.css` → `pages.css`.

## 4. Содержимое `<head>`

Каждая страница: `lang="ru"`, `charset`, `viewport`, уникальные `title` и `description`, `og:title`, `og:description`, `og:image` (1200×630), favicon, `preconnect` и ссылка на Google Fonts (Unbounded, Inter, `display=swap`).

Для тега GA4 (этап 2) в `<head>` оставляется парное место:

```html
<!-- ga4:start -->
<!-- ga4:end -->
```

В будущем между метками вставляется тег `gtag.js` с идентификатором `G-…` (ТЗ 4.1, требуется на всех страницах, включая 404). Идентификатора пока нет, **придумывать его нельзя**.

## 5. Шапка и подвал (решение ADR-1)

ТЗ требует одинаковые шапку и подвал на всех страницах, в меню выделена текущая страница. Без сборки есть три пути.

| Вариант | Плюсы | Минусы |
|---|---|---|
| Копировать разметку в каждый файл | Видна без JS, хороша для SEO и Lighthouse, работает на `file://` | Меняя шапку, правишь 9 файлов |
| Вставлять скриптом через `fetch` | Один источник | Не работает на `file://`; без JS шапки нет |
| Вставлять скриптом из строки в JS | Один источник, работает на `file://` | Без JS шапки нет |

**Решение: копировать.** Девять страниц это мало, а `tools/check.py` сравнивает шапки и подвалы и показывает расхождения. Отличается только `aria-current="page"`.

Шапка (по Приложению А): логотип-ссылка на главную, меню («Курсы», «Меню», «Зерно», «Контакты»), телефон (`contact_click`), кнопка «Записаться»; на узком экране кнопка-бургер (`aria-expanded`, не меньше 44×44 px). Подвал: адрес, соцсети (`social_click`), ссылка на `privacy.html`.

## 6. JS-слой

### 6.1. `analytics.js`: единственное место для событий

ТЗ 4.3: все вызовы `gtag('event', …)` находятся в одном файле `js/analytics.js`. Файл делает четыре вещи, каждая в своей функции:

1. **Заглушка `gtag`.** `window.dataLayer = window.dataLayer || []; function gtag() { dataLayer.push(arguments); }`. Пока настоящего тега нет, события копятся в `dataLayer`; когда вставят тег GA4, они пойдут в аналитику без изменений кода.
2. **Сбор UTM.** При загрузке любой страницы читает `utm_source`, `utm_medium`, `utm_campaign`, `utm_content` из адреса и сохраняет в `sessionStorage` (ТЗ 6.3), чтобы метки не терялись при переходах по сайту. Если метки в адресе нет, ничего не перезаписывает.
3. **`Z7.track(name, params)`.** Вызывает `gtag('event', name, params)`. Её вызывают другие скрипты (`quiz.js`, `form.js` и др.), потому что сами они `gtag` не трогают.
4. **Разбор `data-event`.** Один обработчик клика на документе: если у нажатого элемента (или его родителя) есть `data-event`, собирает параметры из остальных `data-*` и вызывает `Z7.track`.

Пример из ТЗ и правило имён атрибутов: `data-event="cta_click" data-button-name="hero_trial"` даёт `gtag('event', 'cta_click', {button_name: 'hero_trial'})`. Дефисы в имени атрибута становятся подчёркиваниями в имени параметра: `data-page-section` → `page_section`.

Правила (ТЗ 4.3): имена событий и параметров в `snake_case`, не длиннее 40 символов; значения не длиннее 100 символов; **в GA4 не передаются имя, телефон и e-mail посетителя** ни в параметрах, ни в адресе страницы.

### 6.2. Какие события кем отправляются

| Способ | События |
|---|---|
| Атрибуты `data-event` в разметке (клик) | `cta_click`, `view_course`, `select_course_date`, `menu_filter`, `bean_view`, `promo_copy`, `contact_click`, `messenger_click`, `social_click`, `map_open`, `gallery_view` |
| Вызов `Z7.track` из скрипта | `quiz_complete`, `form_error`, `generate_lead` |
| Автоматически (расширенная статистика GA4, кода нет) | `page_view`, `scroll`, `click` (внешние ссылки), `file_download`, `form_start`, `form_submit` |

Таблица со всеми параметрами — в [data-schema.md](data-schema.md). Журнал «где отправляется (файл и строка)» ведёт исполнитель в `docs/events.md`.

### 6.3. Остальные скрипты

| Файл | Что делает |
|---|---|
| `common.js` | мобильное меню; `Z7.fmt.rub`, `Z7.fmt.date`, `Z7.fmt.seats` (форматирование цены, даты, «Осталось 3 места») |
| `quiz.js` | тест на главной по [quiz.md](quiz.md) |
| `courses.js` | потоки с местами из `ZERNO.intakes`, неактивные потоки |
| `menu.js` | фильтр меню |
| `beans.js` | карточки сортов (если нужны данные из `data.js`) |
| `guide.js` | копирование промокода |
| `gallery.js` | открытие фото |
| `form.js` | форма заявки (раздел 7) |
| `thanks.js` | показ номера заявки |

Каждый скрипт запускается после `DOMContentLoaded` и сам находит свои элементы; если элемента на странице нет, молча выходит.

## 7. Форма заявки (ТЗ 6.3)

**Поля пользователя:** `name`, `phone`, `email`, `course`, `start_month`, флажок согласия (не отмечен, обязателен, ссылка на `privacy.html` в подписи).

**Скрытые поля:** `request_id`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`. Заполняет JS: UTM из `sessionStorage`, при отсутствии значения по умолчанию `direct`, `none`, `not_set`, `not_set` (ТЗ 6.1). `request_id` = `REQ-` + UUID (`crypto.randomUUID()`).

**Значения списков:** `course` ∈ `barista_basic`, `latte_art`, `alternative`, `corporate`; `start_month` ∈ `dec_2026`, `jan_2027`, `feb_2027`. Метки для людей берутся из `data.js`.

**Проверка на клиенте** (приёмник проверит ещё раз): `name` 2–60 символов; `phone` «+7 и 10 цифр»; `email` не обязателен, но если заполнен, формат адреса; все строки не длиннее 200 символов; согласие отмечено. Ошибка: поле подсвечено, под ним понятный текст, фокус на первом ошибочном поле, отправляется `form_error` (`field_name`, `error_type` из `empty`, `format`, `consent`, `server`).

**Отправка:** без перезагрузки страницы, через `fetch`; пока идёт запрос, кнопка неактивна. Запрос `POST` на `ZERNO.form.endpoint`, тело JSON, заголовок `Content-Type: text/plain;charset=utf-8` (так браузер не делает предварительный запрос, и веб-приложение Apps Script обычно отвечает без ошибки CORS; **проверить на этапе 3**). Ответ приёмника: `{"ok": true}` или `{"ok": false, "error": "…"}`.

**Результат:**
- `ok: true` → `Z7.track("generate_lead", {lead_course, lead_source})` (`lead_source` берётся из `utm_source`) → переход на `thanks.html?request_id=<request_id>`;
- иначе → `form_error` с `error_type = "server"`, форма остаётся, показано сообщение.

**Демо-режим.** Приёмника (этап 3) ещё нет, `ZERNO.form.endpoint` равен `null`. Тогда `form.js` **не отправляет запрос**, пишет в консоль «демо-режим: заявка никуда не отправлена» и выводит туда данные заявки (так проверяются UTM-метки), после чего ведёт себя так, будто пришёл `ok: true`. В README это написано прямо. Когда появится адрес приёмника, меняется одна строка в `data.js`.

**Личные данные** нигде не сохраняются в браузере: в `sessionStorage` лежат только UTM-метки. В адресе страницы и в GA4 нет имени, телефона и e-mail.

## 8. Связи между страницами

| Откуда | Куда |
|---|---|
| Любая кнопка записи | `contacts.html?course=<course>` |
| «Выбрать поток» | `contacts.html?course=<course>&intake=<intake>` |
| Результат теста | `contacts.html?course=<quiz_result>` |
| Гид по латте-арту | `contacts.html?course=latte_art` |
| Заказ зерна | `contacts.html` |
| Карточка курса на главной | `courses.html#course-<course>` |
| После успешной отправки | `thanks.html?request_id=<request_id>` |

`<course>` — код курса из `data.js`, `<intake>` — идентификатор потока. Форма читает параметры и выбирает курс и месяц старта (из потока). Без параметров всё пусто, ничего не ломается. UTM-метки в ссылки между страницами копировать не нужно: их хранит `sessionStorage`.

## 9. Деплой

Vercel подключается к репозиторию как статический проект: Framework Preset — `Other`, команды сборки нет, Output Directory — корень. Ветка `main` — боевой сайт, остальные ветки получают адреса предпросмотра ([workflow.md](workflow.md)). Файл `404.html` в корне Vercel отдаёт сам. Домен `zerno7.example` не используется (ТЗ, стр. 4): адрес вида `<имя>.vercel.app`.

## 10. Производительность и доступность (Lighthouse)

- Первый экран: одно изображение ≤ 300 КБ, `width` и `height` заданы, без ленивой загрузки; остальные с `loading="lazy"`.
- Шрифты: `preconnect`, `display=swap`, не больше четырёх начертаний.
- Один `<h1>`, заголовки без пропуска уровней, у каждого поля `<label>`, видимый фокус, ссылка «Перейти к содержанию».
- Нет сдвигов раскладки: у картинок и галереи резервируется место.
- Анимации по желанию, но с `prefers-reduced-motion`.
- **Lighthouse в ТЗ проверяется на главной с тегом GA4**: замерьте ещё раз после этапа 2. Тег добавит нагрузку, поэтому запас по Performance (порог 70) нужен.
