# Архитектура сайта «Зерно 7»

Требования — [spec.md](spec.md), данные и события — [data-schema.md](data-schema.md).

## 1. Принципы

1. **Без сборки и фреймворков.** Чистые HTML, CSS, JS. Ни `npm`, ни бандлеров.
2. **Работает по двойному клику (`file://`) и на Vercel одинаково.** Отсюда два запрета: нет `<script type="module">` и нет `fetch()` локальных JSON. Браузер блокирует оба на `file://`. Данные лежат в `js/data.js` как обычный скрипт.
3. **HTML содержит содержание, JS добавляет поведение.** Тексты, цены и заголовки лежат в самой разметке: так их видят поисковики, и Lighthouse SEO проходит. JS нужен для теста, мест в потоках, фильтра меню, формы, копирования промокода.
4. **Факты берутся только из `js/data.js`.** Всё, чего там нет, на сайте не публикуется.
5. **Пути относительные** (`css/base.css`, а не `/css/base.css`), так работает и локально, и на Vercel.

Страницы лежат в корне: имена файлов в ТЗ без папок, и Vercel сам отдаёт `404.html` из корня.

## 3. Подключение к странице

Каждая страница в конце `<body>` подключает скрипты **с `defer` и именно в таком порядке**:

```html
<script src="js/data.js" defer></script>
<script src="js/common.js" defer></script>
<script src="js/courses.js" defer></script>   <!-- только скрипт этой страницы -->
```

CSS в `<head>`: `tokens.css` → `base.css` → `components.css` → `pages.css`. Это четыре маленьких запроса. Если будет сильно мешать Performance, объедините в один файл, ничего не сломается.

## 4. Шапка и подвал (решение ADR-1)

**Контекст.** ТЗ требует одинаковые шапку и подвал на всех страницах. Без сборки есть два пути.

| Вариант | Плюсы | Минусы |
|---|---|---|
| Копировать разметку в каждый файл | Видна без JS, хорошо для SEO и Lighthouse, работает на `file://` | Меняя шапку, нужно править 9 файлов |
| Вставлять скриптом (`fetch` фрагмента) | Один источник | Не работает на `file://`; без JS шапки нет |
| Вставлять скриптом из строки в JS | Один источник, работает на `file://` | Без JS шапки нет, хуже для SEO |

**Решение: копировать разметку.** Девять страниц это мало, а скрипт `tools/check.py` сравнивает шапки и подвалы между страницами и сразу показывает, где разошлись. Единственное отличие между копиями — `aria-current="page"` у активного пункта.

Шапка: логотип-ссылка на главную, `<nav>` с пунктами «Курсы», «Меню», «Зерно», «Контакты» и кнопкой «Записаться», на узком экране кнопка-бургер (`aria-expanded`, не меньше 44×44 px). Подвал: режим работы из `data.js`, контакты, соцсети, ссылка на `privacy.html`.

## 5. JS-слой

Глобальное пространство имён `Z7` (в `common.js`), без экспортов:

| Функция | Что делает |
|---|---|
| `Z7.track(name, params)` | `window.dataLayer.push({event: name, ...params})`; с `?debug=1` дублирует в консоль |
| `Z7.fmt.rub(n)` | `14900` → «14 900 ₽» (неразрывный пробел) |
| `Z7.fmt.date(iso)` | `"2026-12-02"` → «2 декабря 2026»; через `new Date(iso + "T12:00:00")`, чтобы часовой пояс не сдвинул день |
| `Z7.fmt.seats(n)` | «Осталось 3 места», «1 место», «5 мест», «Мест нет» (русские формы числительных) |
| `Z7.params()` | разбор `location.search` для `?course=&intake=&promo=&id=` |

Каждый скрипт страницы запускается после `DOMContentLoaded` и сам находит свои элементы по `data-`атрибутам (`data-quiz`, `data-intakes`, `data-filter`). Если элемента на странице нет, скрипт молча выходит.

## 6. Связи между страницами (URL-контракт)

| Откуда | Куда |
|---|---|
| Любая кнопка записи | `contacts.html?course=<courseId>` |
| Кнопка у конкретного потока | `contacts.html?course=<courseId>&intake=<intakeId>` |
| Результат теста | `contacts.html?course=<resultCourseId>` |
| Гид по латте-арту | `contacts.html?course=latte-art&promo=LATTE10` |
| Заказ зерна | `contacts.html#messengers` |
| Карточка курса на главной | `courses.html#course-<courseId>` |
| После отправки формы | `thanks.html?id=<leadId>` |

Форма читает параметры и заранее выбирает курс, поток и промокод. Если параметров нет, всё пусто, ничего не ломается.

## 7. Форма заявки (D2)

1. Поля: имя*, телефон*, e-mail, курс*, поток (список зависит от курса, потоки без мест неактивны), промокод, комментарий, **флажок согласия*** (не отмечен, `required`, ссылка на `privacy.html` в подписи).
2. Проверка на клиенте без `alert()`: сообщения об ошибках рядом с полем, `aria-describedby`, фокус переходит к первой ошибке.
3. Успех: создать `leadId` (формат в [data-schema.md](data-schema.md)) → `Z7.track("generate_lead", …)` → переход на `thanks.html?id=…`.
4. Личные данные не сохраняются ни в `localStorage`, ни в cookies и никуда не отправляются.

## 8. Деплой

Vercel подключается к репозиторию как статический проект: Framework Preset — `Other`, команды сборки нет, Output Directory — корень. Ветка `main` — боевой сайт, любая другая ветка автоматически получает свой адрес предпросмотра: на этом строится сравнение моделей ([workflow.md](workflow.md)).

## 9. Производительность и доступность (чтобы пройти Lighthouse)

- Первый экран: одно изображение до 300 КБ, `width`/`height` заданы, без `loading="lazy"` у него; у остальных `loading="lazy"`.
- Шрифты: `preconnect` к `fonts.googleapis.com` и `fonts.gstatic.com`, `display=swap`, не больше четырёх начертаний.
- Один `<h1>` на страницу, заголовки без пропуска уровней, у `<html>` `lang="ru"`, у каждого поля `<label>`, видимый фокус, ссылка «Перейти к содержанию».
- Нет «layout shift»: у картинок и галереи резервируется место.
- Анимации по желанию, но с `prefers-reduced-motion`.
