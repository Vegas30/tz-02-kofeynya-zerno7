# Что полное ТЗ добавляет к этапу «сайт»

Полный ТЗ № ТЗ-02/2026 (18 страниц): [tz-full.pdf](tz-full.pdf). Файл [tz.md](tz.md) это сокращённая выжимка, из неё выпали важные пункты. Здесь собрано всё, что полное ТЗ требует от сайта. Остальные этапы (GA4, UTM-реестр, таблица и Apps Script, ManyChat, отчёты, DataLens) сейчас не делаются, но сайт должен быть к ним готов.

## 1. Вес сайта в оценке

| Часть работы | Разделы | Баллы |
|---|---|---|
| **Сайт**: страницы, блоки, адаптивность, Lighthouse, публикация, журнал запросов | 3 | **15** |
| Аналитика: ресурс, тег, 18 событий с параметрами, пользовательские параметры, ключевые события | 4 | 25 |
| UTM: реестр, короткие ссылки, QR, публикации в 4 соцсетях, отработка | 5 | 15 |
| Заявки: таблица, приёмник, форма | 6 | 10 |
| Автоответы Instagram | 7 | 10 |
| Отчёты и исследования GA4, атрибуция, оповещение, записка | 8.1–8.3, 8.5 | 10 |
| Дашборд DataLens и статусы заявок | 6.4, 8.4 | 10 |
| Репозиторий и снимки | 11 | 5 |
| Итого | | 100 (+4 за события «по выбору») |

Сайт это 15 из 100 баллов, а большая часть остальной работы делается руками в сервисах (GA4, Google Таблицы, ManyChat, DataLens, соцсети), где агенты не помогут. Не давайте сравнению моделей съесть время на эти этапы.

Работа **не принимается к оценке**, если не выполнено хотя бы одно: сайт открывается по адресу Vercel; тег GA4 есть на всех страницах; контрольная заявка И-03 доходит до таблицы с метками.

## 2. Требования, которых нет в сокращённом ТЗ

| № | Требование (раздел ТЗ) |
|---|---|
| S-01 | Инструмент и версия нейросети указываются в `docs/prompts.md` (3.1) |
| S-02 | В `docs/prompts.md` минимум: запрос на структуру сайта, **отдельный запрос на каждую страницу** и запросы на исправления (3.1) |
| S-03 | При приёмке заказчик выбирает **любой фрагмент JS из `js/`**, и вы объясняете, что делает каждая строка (3.1) |
| S-04 | Не меньше 10 коммитов с понятными сообщениями; **первый коммит — исходный результат нейросети без правок** (3.4) |
| S-05 | Адрес `<имя>.vercel.app` в README; домен `zerno7.example` не используется (3.4, стр. 4) |
| S-06 | Все вызовы `gtag('event', …)` в одном файле `js/analytics.js`; кнопки описываются атрибутами `data-event`, `data-button-name` (4.3) |
| S-07 | Имена событий и параметров в `snake_case` ≤ 40 символов, значения ≤ 100; имя, телефон и e-mail в GA4 не передаются (4.3) |
| S-08 | `generate_lead` только после ответа приёмника `ok: true`; при ошибке `form_error` с `error_type = "server"` (4.3) |
| S-09 | Таблица событий в `docs/events.md`: имя, файл и строка, параметры с примерами (4.3) |
| S-10 | Сайт отправляет события 4.2: 12 своих обязательных, 2 «по выбору» (`map_open`, `gallery_view`), 6 автоматических собирает GA4 |
| S-11 | UTM-метки читаются из адреса и сохраняются в `sessionStorage` на любой странице (6.3) |
| S-12 | Форма: поля `name`, `phone`, `email`, `course`, `start_month`, согласие; скрытые `request_id` (`REQ-` + UUID) и 4 UTM-поля; отправка через `fetch` без перезагрузки; кнопка неактивна во время отправки; успех ведёт на `thanks.html` с номером заявки; ошибка подсвечивает поле, показывает текст и шлёт `form_error` (6.3) |
| S-13 | Структура репозитория по разделу 11: `css/`, `js/analytics.js`, `js/form.js`, `img/`, `files/`, `docs/`, `screens/lighthouse/`, `README.md` |
| S-14 | README начинается с таблицы ссылок (сайт на Vercel и др.); в конце две строки: «Не получилось: ___» и «Нейросеть использовалась для: ___» (11) |
| S-15 | Снимок отчёта Lighthouse главной в `screens/lighthouse/` (11) |
| S-16 | Этап «Сайт» должен быть готов к **дню 4** от даты выдачи ТЗ; промежуточный результат заказчик может проверить без предупреждения (9) |
| S-17 | В 3.2 уточнено: `404.html` в составе сайта. В политике (`privacy.html`) оператор ООО «Зерно Семь», реквизиты из шапки ТЗ |

## 3. Приёмочные испытания, которые касаются сайта (раздел 10)

| № | Что делает заказчик | Ожидаемый результат |
|---|---|---|
| И-01 | Открывает все страницы по адресу Vercel в режиме телефона (375 px) | Страницы открываются, нет горизонтальной прокрутки, меню работает |
| И-02 | Открывает исходный код трёх страниц на выбор | В `<head>` есть тег с идентификатором ресурса (этап 2) |
| И-03 | Переходит по ссылке реестра со своего телефона и отправляет заявку с именем «Приёмка ТЗ-02/2026» | Строка в таблице с метками, `generate_lead` в DebugView (этапы 2–3) |
| И-04 | Отправляет форму с пустым телефоном, затем с телефоном «123» | Форма не отправлена, ошибка у поля, событие `form_error` |
| И-06 | Называет 5 событий из таблицы 4.2 | Исполнитель вызывает каждое на сайте и показывает параметры в DebugView |
| И-13 | Проходит тест, выбирая во всех вопросах первый вариант | Показан курс и кнопка записи; в DebugView `quiz_complete` с `quiz_result` |

Остальные испытания (И-05, И-07–И-12) относятся к приёмнику, ManyChat, DataLens и отчётам.

## 4. Что отложено, но влияет на сайт сейчас

| Этап | Что нужно от сайта уже сейчас |
|---|---|
| 2. GA4 | В `<head>` каждой страницы пустое место между `<!-- ga4:start -->` и `<!-- ga4:end -->`; `Z7.track` пишет в `dataLayer`, поэтому после установки тега события пойдут сами; `ZERNO.analytics.measurementId` не придумывать |
| 3. Заявки | Формат полей и ответ `{"ok": ...}` уже заложены; в `data.js` остаётся вписать `form.endpoint`; код приёмника позже в `apps-script/Code.gs` |
| 4. Каналы и UTM | Сайт сохраняет метки в `sessionStorage`; целевые страницы реестра: `index`, `latte-guide`, `beans`, `courses` |
| 7. ManyChat | Страницы `latte-guide.html` (ветка «ЛАТТЕ») и `beans.html` (ветка «ЗЕРНО») принимают метки из адреса |
| 8. Отчёты | Воронка GA4: `page_view` → `view_course` → `cta_click` → `form_start` → `generate_lead`; значит, на сайте должна быть цепочка «карточка курса → кнопка заявки → форма» с этими событиями |

## 5. Сроки по ТЗ (раздел 9)

День 0 — дата выдачи (в вашем экземпляре поле «Дата выдачи» пустое). Сайт к дню 4, аналитика к дню 8, заявки к дню 11, каналы к дню 15, отчёты к дню 19, сдача на день 21. Если выдача сегодня, 8 ноября, то сайт нужен к 12 ноября: календарь в [workflow.md](workflow.md) рассчитан на это.
